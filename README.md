# Web Application Security Lab

Учебный проект по информационной безопасности. Разработка веб-приложения
на Python с намеренно реализованными уязвимостями SQL Injection и
Cross-Site Scripting (XSS), демонстрация их эксплуатации и последующее
исправление.

## 1. Цель работы

Изучить основы веб-разработки и принципы безопасности веб-приложений:

- Клиент-серверную архитектуру.
- Протокол HTTP и методы GET/POST.
- Разработку веб-приложений на стандартной библиотеке Python.
- Работу с базами данных SQLite.
- Механизмы эксплуатации SQL Injection и XSS.
- Методы устранения обнаруженных уязвимостей.

## 2. Используемые технологии

- Python 3 (только стандартная библиотека)
- http.server
- SQLite (модуль sqlite3)
- HTML
- urllib
- Git / GitHub

Внешние зависимости не требуются — приложение работает на «чистом» Python 3.

## 4. Установка и запуск

Клонирование репозитория:

```bash
git clone https://github.com/Smith-kuz/web-security-lab.git
cd web-security-lab
```

Запуск уязвимой версии (база данных создаётся автоматически при запуске):

```bash
python app.py
```

Приложение будет доступно по адресу:

http://127.0.0.1:8000/

Тестовые учётные записи:

- `admin` / `S3cr3t_Admin_Pass!`
- `alice` / `qwerty123`
- `bob` / `password`

## 5. Реализованные уязвимости

### 5.1. SQL Injection

Уязвимость реализована в обработчике авторизации `/login`.

Причина возникновения: непосредственная подстановка пользовательских
данных в SQL-запрос с использованием форматирования строки.

Это позволяет изменить логику SQL-запроса, обойти проверку учётных данных
и извлечь содержимое базы данных.

Эксплуатация:

```bash
python exploit.py
```

Скрипт отправляет специально сформированные POST-запросы и демонстрирует
обход авторизации, а также выгрузку логинов и паролей всех пользователей
с помощью UNION-инъекции.

### 5.2. Cross-Site Scripting (XSS)

Уязвимость реализована в обработчике заметок `/notes` (хранимый XSS) и
в обработчике поиска `/search` (отражённый XSS).

Причина возникновения: непосредственная вставка пользовательского ввода
в HTML без экранирования.

В результате браузер интерпретирует переданные данные как исполняемый
JavaScript-код. Сохранённый в заметке скрипт выполняется у каждого, кто
открывает страницу `/notes`; параметр поиска отражается в ответе и
позволяет провести атаку по вредоносной ссылке.

Проверка отражения полезной нагрузки также выполняется скриптом
`exploit.py`.

## 6. Исправление уязвимостей

Исправления оформлены в виде патчей в каталоге `patches/` (формат unified diff).

### SQL Injection

Вместо формирования SQL-запроса через форматирование строки используются
параметризованные запросы SQLite (плейсхолдеры `?`). Данные передаются
отдельно от текста запроса, поэтому не могут изменить его структуру.

### XSS

Любой пользовательский ввод перед вставкой в HTML экранируется функцией
`html.escape()`, которая преобразует символы `< > & "` в безопасные
HTML-сущности. В результате внедрённый код отображается как текст и
не выполняется.

Применение патча:

```bash
# исправить обе уязвимости
patch -p1 < patches/fix_all.diff

# или через git
git apply patches/fix_all.diff
```

После применения патча повторный запуск `exploit.py` подтверждает, что
прежние атаки больше не срабатывают.

## 7. Файлы исправлений

Каталог `patches/` содержит три файла в формате diff:

- `fix_all.diff` — устраняет обе уязвимости сразу;
- `fix_sqli.diff` — устраняет только SQL Injection;
- `fix_xss.diff` — устраняет только XSS (хранимый и отражённый).

Они демонстрируют точные изменения, внесённые в `app.py` для устранения
уязвимостей.

## 8. Ограничения проекта

Проект предназначен исключительно для учебной демонстрации.

В уязвимой версии намеренно используются небезопасные способы обработки
пользовательских данных. Пароли тестовых пользователей хранятся в открытом
виде для упрощения демонстрации SQL Injection.

Не использовать приложение в производственной среде и не размещать его
в открытом доступе в сети.
